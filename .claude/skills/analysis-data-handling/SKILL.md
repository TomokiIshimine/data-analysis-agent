# analysis-data-handling — データの取り込み・記録・検証・機密取り扱い規約

## 適用場面

分析対象データに触れるすべての工程で参照する。利用者は次の 5 体。

| 役割 | 参照する主な節 |
|---|---|
| `data-ingestion-profiler`（台帳の書き手） | データソースの解決 / 台帳の記録項目 / 取り込み方式の判定 |
| `analysis-executor`（ハッシュ照合・派生データ） | 同一性の検証 / 機密区分 |
| `analysis-report-author`（台帳の転記・掲載判断） | レポートへの転記 / 機密区分 |
| `analysis-report-stylist`（掲載判断） | 機密区分 |
| `reproduction-verifier`（ハッシュ照合・掲載判断） | 同一性の検証 / 機密区分 |

## 1. データソースの解決

自然文（`analysis-request`）からデータの所在を読み取る。想定するソース形態は、ローカルファイル・ディレクトリ・DB 接続・API / URL・およびそれらの組み合わせ。

- 明示されたパス・接続先・エンドポイントは、そのまま解決対象とする。ディレクトリが指定された場合は配下のデータファイルを列挙し、各ファイルを個別のソースとして扱う。
- 相対パスで書かれている場合はプロジェクトルートからの相対と解釈し、台帳には **絶対パス** で記録する。
- **特定できない場合、推測で手近なファイルを選ばない。** 候補を列挙して「未確定」として記録し、確定はユーザーの承認ゲートに委ねる。誤ったデータで要件を固めて分析を何周も回した場合の損失が、確認 1 往復のコストを大きく上回るため。
- 未確定として記録する場合、プロファイルレポートの `## データソース` に `UNRESOLVED` の 1 語と、候補一覧（各候補の所在・サイズ・推測される内容・なぜ候補としたか）を書く。推奨候補があれば理由とともに示す。
- 解決できた場合は `## データソース` に `RESOLVED` の 1 語と、解決したソースの一覧を書く。
- 確定したデータソースが引数として明示的に渡された場合（承認ゲート後の再解決）、それを **唯一の正** とし、他の候補を探索しない。

## 2. `data/manifest.md` の記録項目

台帳は **データの所在に関する唯一の情報源** である。各ソースについて以下を記録する。

| 項目 | 内容 |
|---|---|
| ソース識別子 | 以後すべての工程がこのデータを指すのに使う短い名前（`sales_2024`, `customer_master`）。実行スクリプト・`environment.md`・レポートからこの識別子で参照する |
| 所在 | ローカルなら絶対パス。DB なら接続先の **名前**（環境変数名・シークレット名）とスキーマ・テーブル。API なら エンドポイント URL |
| 取得方法 | 再現に必要な決定的な手順。コマンド、SQL クエリ（並び順・期間・条件を含む）、リクエストパラメータ |
| SHA-256 | 対象データのハッシュ値。DB / API 由来は、決定的に書き出した結果に対して計算する |
| サイズ | バイト数 |
| 件数 | 行数・レコード数 |
| スキーマ | 列名と型の一覧 |
| 取得日時 | タイムゾーン付き |
| 機密区分 | 後述の区分。暫定値の段階ではその旨を明記する |
| 取り込み方式 | `参照` / `コピー` / `スナップショット` のいずれか。コピー・スナップショットの場合は保存先パスも記録する |

台帳は追記形式で運用し、再解決で内容が変わった場合は旧エントリを消さず、更新日時とともに履歴が辿れる形にする。

## 3. 取り込み方式の判定

**既定は参照（複製しない）。** 再現性に必要なのは「同じデータであることを検証できること」であり、複製そのものではない。ハッシュ照合があれば元データの差し替えを検知できる。

| 条件 | 方式 |
|---|---|
| 既定（上記の例外に当たらないすべて） | **参照**。台帳に所在・ハッシュ・件数・スキーマを記録し、原本はコピーしない |
| 非機密かつ小容量（既定 100 MB 未満）のローカルファイル | `data/raw/` に **コピー**してよい。閾値は要件シートで上書きできる |
| 再取得で内容が変わりうる **非機密** ソース（DB クエリ・API・時刻依存の抽出） | `data/snapshot/` に **決定的スナップショット**を保存する。同時に、そのスナップショットを再生成できる取得クエリ・抽出条件を台帳に記録する |
| **機密データ**（区分が未確定のものを含む） | コピーもスナップショットも **しない**。決定的な取得クエリと抽出条件のみ記録する |

- 機密区分が確定していない段階では、機密の可能性があるものとして扱い、作業ディレクトリに複製しない（保守側に倒す）。区分は要件シートで確定する。
- コピー・スナップショットを作った場合も、台帳の SHA-256 は **原本** に対する値と、保存物に対する値の両方を記録し、同一であることを示す。

## 4. 同一性の検証

分析実行の直前と、再現追試でデータを入手した直後に、台帳記載の **SHA-256 と件数** を実データに対して照合する。

- 照合対象は台帳に記録されたすべてのソース。分析に使うソースだけでなく、前処理の入力になるものを含める。
- **不一致の場合は処理を進めない。** 期待値・実測値・対象パス（またはソース識別子）を実行ログ／検証レポートに記録して終了する。元データが差し替わったまま分析した結果は再現できないため、自動で台帳を更新して続行してはならない。
- 台帳に載っていないデータを分析の入力に使わない。必要なデータが増えた場合は、台帳への追加が先である。
- 再現追試では、レポート記載のハッシュ・件数・スキーマと、入手したデータの実測値を突き合わせる。**データが入手できない、またはハッシュが一致しない場合は、分析結果の一致にかかわらず再現失敗として扱う**（同じデータに辿り着けないなら再現できていない）。

## 5. 機密区分

区分は要件シートでユーザーが確定する。判断材料が不足する場合は **保守側（掲載制限が厳しい側）** を既定とする。区分ごとの取り扱いは次のとおり。

| 区分 | 作業ディレクトリへのコピー | レポート本文への生データ掲載 | 図表への個票表示 | 必要な処理 |
|---|---|---|---|---|
| **公開可**（公開データ・サンプルデータ） | 可（容量条件の範囲で） | 可 | 可 | なし |
| **社内限定**（業務データ、個人を特定しない） | 可（容量条件の範囲で） | 集計値のみ可。生データの行は不可 | 集計・分布のみ可 | 下記「集約の下限件数」を満たすこと |
| **機密**（個人情報・取引先情報・認証情報を含む） | **不可** | **不可** | **不可** | マスキングまたは集約を施した派生値のみを扱う |
| **未確定** | **不可**（機密として扱う） | **不可** | **不可** | 区分の確定を待つ |

- **マスキングの要件**: 機密区分のデータを扱う場合、個人・個社を特定できる列（氏名・住所・メールアドレス・電話番号・個別 ID）は分析の入力から落とすか、復元不能な形に変換する。
- **集約の下限件数**: 社内限定・機密のデータから作った集約値を掲載する場合、**1 グループの構成件数が 5 件未満のセルは掲載しない**。該当セルは上位グループへ併合したうえで掲載するか、非掲載とする。この下限件数（既定 5 件）は要件シートで上書きできる。実データに対して下限を満たすか判定できない場合は掲載しない。
- 掲載可否の判断に迷う場合は **載せない**。再現可能レポート（Markdown）と清書レポート（HTML）は第三者に共有される前提の成果物であり、埋め込んだ機密は回収できない。
- 掲載を見送った場合は、その事実と理由を該当箇所に明記する（黙って省略しない）。代わりに「同じデータをどう入手し、どう同一性を検証するか」を記述する。
- 検証レポート・実行ログ・プロファイルレポートにも同じ掲載制限を適用する。作業ディレクトリ内だからといって生データ・個票を貼らない。

## 6. 認証情報の扱い

- 接続文字列・トークン・パスワード・API キー・証明書そのものを、台帳・プロファイル・スクリプト・実行ログ・レポートのいずれにも書かない。
- 記録するのは **参照先の名前** のみ（環境変数名・シークレット名・認証方式）。スクリプトは環境変数等から読み込む形で書く。
- 標準出力・標準エラー・エラーメッセージに秘密値が現れうる場合は、保存前に伏せる。
- URL のクエリ文字列に含まれるトークンにも同じ扱いを適用する。台帳にはトークン部分を除いたエンドポイントを記録する。

## 7. レポートへの転記

再現可能レポート（Markdown）と清書レポート（HTML）は、**作業ディレクトリの台帳を参照できない第三者** に単体で渡る成果物である。したがって台帳の内容をレポート本文に転記する。

- **転記する項目**: ソース識別子・所在（機密区分が許す範囲）・取得方法（コマンド／クエリ／エンドポイント）・SHA-256・サイズ・件数・スキーマ・取得日時。読者が「同じデータを手に入れて、同一性を検証できる」状態にする。
- **台帳ファイルへの参照だけで済ませない。**「詳細は `data/manifest.md` を参照」はレポート単体で完結しないため不可。
- 転記は再現に必要な項目に限る。台帳の全文をそのまま貼らない。
- 機密区分が所在の記載を許さない場合（社内の接続先名など）は、その旨と、読者が同等のデータを入手するための条件を記述する。
- レポートの再現手順は **データの入手と同一性検証を最初の手順** として置く。データに辿り着けないレポートは、以降の手順がどれだけ正確でも再現できない。
- 転記元は台帳 1 つ、レポート側は転記であり、両者が食い違った場合は台帳を正とする。

## 本スキルが定めないもの

- 実行資産の保存構成（`analysis-run-recording` の責務）。
- 分析手法や前処理の内容（要件シートと各周回のプランが決める）。
- 機密区分の具体的な値（要件シートでユーザーが確定する）。
- HTML 成果物の見た目（`html-deliverable-design` の責務）。
