# analysis-run-recording — 実行資産の保存規約

## 適用場面

コードを実行して結果を残すすべての工程で参照する。書き手は「コードを実行して記録を残す係」（プロファイリング／分析の各周回／再現追試）、読み手は「保存済みの実行資産を読んでレポートを組み立てる係」。書き手が複数いても同じ構造で保存し、読み手が同じ前提で読めるように 1 本に集約している。本スキルの契約は特定のサブエージェントに依存しない（本プロジェクトでの現在の書き手は `data-ingestion-profiler` ／ `analysis-executor` ／ `reproduction-verifier`、読み手は `analysis-report-author`）。

本スキルで **台帳** と呼ぶのは、分析対象データの所在・同一性・取り扱い区分を記録した一覧である。記録項目は `analysis-data-handling` が定める。台帳が実際にどのパスに置かれるかは呼び出し元のワークフローが決める情報であり、本スキルは定めない。スクリプトや `run.sh` が台帳を必要とする場合、その所在は実行時に引数・環境変数で渡される。

## 合格条件

**「後日 `run-dir` だけを渡された人が、`run.sh` を流して同じ結果に至れるか」** を保存の唯一の合格条件とする。この問いに「はい」と答えられない保存は、内容がどれだけ詳しくても不合格である。

## `run-dir` 配下の構成

| パス | 内容 |
|---|---|
| `<run-dir>/scripts/<NN>_<slug>.<ext>` | 実行したスクリプトの実体。`<NN>` は実行順の 2 桁連番（`01`, `02`, …）。前処理スクリプトも含む |
| `<run-dir>/run.sh` | `scripts/` を実行順に呼び出す再実行エントリポイント |
| `<run-dir>/environment.md` | 実行環境の記録 |
| `<run-dir>/derived/<NN>_<slug>.<ext>` | 前処理で生成した派生データ。`run.sh` の実行で再生成可能であること |
| `<run-dir>/outputs/<NN>_<slug>.stdout.txt` / `<NN>_<slug>.stderr.txt` | 各スクリプトの標準出力・標準エラー |
| `<run-dir>/figures/<NN>_<slug>.png` | 生成した図表の実体 |
| `<run-dir>/run-manifest.md` | 実行順・各スクリプトの目的・終了コード・生成物の対応表 |

### 命名規約

- `<NN>` は実行順の 2 桁連番。同じ処理に属するスクリプト・派生データ・出力・図表は **同じ `<NN>_<slug>`** で対応づける。`scripts/03_aggregate_by_month.py` の標準出力は `outputs/03_aggregate_by_month.stdout.txt`、生成図表は `figures/03_aggregate_by_month.png` となる。
- `<slug>` は処理内容が分かる英小文字スネークケース（`load_raw`, `clean_missing`, `fit_model`）。`script1`, `tmp`, `test` のような内容を示さない名前を使わない。
- 1 つのスクリプトが複数の図表を出す場合は `figures/03_aggregate_by_month_<suffix>.png` のように接尾辞で区別し、`<NN>` は変えない。

## 原則: 実行するコードは必ずファイルとして保存してから実行する

- ワンライナー・ヒアドキュメント・対話セッションでの実行で済ませない。**先に `scripts/` にファイルとして書き出し、そのファイルを実行する**。
- 「実行してから、後でスクリプトに書き起こす」順序を取らない。書き起こしの過程で実際に流したコードとの差異が入り込み、再現できなくなる。
- ログや実行レポートに貼るコードは、保存済みスクリプトの **引用** である。実体はスクリプトファイル 1 つであり、ログ側の掲載は実体の代わりにならない。引用は保存済みファイルと文字単位で一致させる（要約・整形による改変をしない）。

## スクリプトのパラメータ化

- スクリプトに **周回番号・周回の呼称（「第 4 周」等）・`run-dir` の絶対パス／相対パスをハードコードしない**。これらはスクリプトの外から与える。
- `run.sh` は自身の位置から `run-dir` を解決し、環境変数 `RUN_DIR` として各スクリプトへ渡す。スクリプトは出力先を `RUN_DIR` を基準に組み立てる。`RUN_DIR` が未設定の場合、スクリプトは既定値で黙って動かず、エラーで停止する（誤った場所へ書き出す事故を防ぐため）。
- 周回の識別は `run-manifest.md` 冒頭の 1 行（この `run-dir` が何の実行か）が唯一の担い手である。スクリプトの内部・コメント・標準出力・生成物のテキストに周回呼称を埋め込まない。
- スクリプトを他の周回へ流用する場合、複製前に上記が守られていることを確認する。守られていないスクリプトは無改変で複製せず、パラメータ化してから複製する。無改変の複製は、生成物に前周の周回呼称と誤った生成元パスをそのまま持ち込む。
- 台帳の所在をスクリプトが必要とする場合も同様に、`run.sh` が環境変数で渡す。スクリプトに台帳のパスを埋め込まない。

## `run.sh` の要件

- **引数なしで先頭から実行でき、完走すること**。実行前に手作業の準備を要求しない。
- **`run-dir` をカレントディレクトリとして動作すること**。冒頭で自身の位置へ移動し、以降のパスはそこを基準にする。相対パスの基準がどこかを冒頭のコメントで明示する。
- `scripts/` を `<NN>` の昇順に呼び出す。各呼び出しで標準出力・標準エラーを対応する `outputs/` のファイルへ振り分ける。
- 途中のスクリプトが失敗したら、その事実が分かる形で終了する（成功を装って続行しない）。
- 入力データの所在は台帳の記録に基づいて解決する。`run.sh` の中に、台帳に載っていないファイルパスを直接埋め込まない。

## `environment.md` に記録する項目

- 言語・ランタイムの名称とバージョン（パッチバージョンまで）
- 依存ライブラリとそのバージョン（ロックファイルがあればその内容、なければ実測したバージョン一覧）
- 乱数シードの値と、それを設定している箇所
- 実行日時（タイムゾーン付き）
- OS とアーキテクチャ
- **入力データについては台帳の該当エントリを識別子で参照するに留め、内容を再掲しない**。データの記録は `analysis-data-handling` の担当領域であり、両方に同じ項目を書くと片側だけが古くなる。

## 派生データの扱い

- 前処理の産物は **必ずスクリプト経由で `derived/` に出力する**。
- 手作業で作った中間ファイル（表計算ソフトで編集した CSV、対話セッションで書き出したファイル）を分析の入力にしない。再現できなくなるため。
- 前処理の入力は必ず台帳に記録された原データから始める。`derived/` の中身は `run.sh` の実行だけで再生成できる状態を保つ。
- `derived/` のファイルが大きい場合も、生成スクリプトを削除しない。実体を残すか否かは容量の判断でよいが、**生成手順は必ず残す**。

## 再実行時に結果を変えうる要素の固定

以下は明示的に固定し、固定した値を `environment.md` とスクリプト内の両方から辿れるようにする。

| 要素 | 固定方法 |
|---|---|
| 乱数 | シードを定数として明示し、使用するすべてのライブラリの乱数生成器に設定する |
| 実行時刻 | 「現在時刻」を処理に使わない。基準日時が必要なら定数として与える |
| ネットワーク取得 | 取得結果をスナップショットとして保存し、再実行はスナップショットを読む。保存できない場合は決定的な取得クエリ（期間・条件・並び順を含む）を記録する |
| 並列実行・スレッド数 | 結果に影響する場合は数を固定する |
| ソート順が不定な処理 | 明示的なソートキーを与えて順序を決定的にする |
| ファイルの列挙順 | 列挙結果を必ずソートしてから使う |
| `run-dir` の所在 | `run.sh` が自身の位置から解決して `RUN_DIR` で渡す。スクリプト側にパスを埋め込まない |

**固定できない要素がある場合は、隠さずに `environment.md` と `run-manifest.md` に「再実行で変わりうる箇所」として明記する**。再現できない箇所を黙って残すことが、再現検証で最も高くつく。

## 失敗の記録

- **失敗したスクリプトを削除しない**。そのまま `scripts/` に残す。
- 終了コード・標準エラーの全文を `outputs/` に保存し、`run-manifest.md` の該当行に終了コードと失敗の要約を記録する。
- エラーで完走できなかった場合も、失敗したところまでの資産（スクリプト・出力・派生データ）を保存して終了する。成功を装った書き換えや、失敗の痕跡の削除をしない。
- 失敗後に修正して再実行した場合、失敗版と修正版の両方を残す（`<NN>` を変えるか、`run-manifest.md` で経緯を記録する）。どちらが最終的に採用されたかを `run-manifest.md` に明記する。

## 確定した run-dir は後から書き換えない

- 一度その周回の成果物として確定した `run-dir` は、後続の周回から書き換えない。各周回の実行ログは当該時点の `run-dir` を前提に書かれているため、後続周が上流を改変すると記録と実体が時点でずれ、読み手（レポート作成者）が索引として使えなくなる。
- 上流の `run-dir` に欠陥（`run.sh` が終了コードを伝播しない、索引に欠落がある 等）が見つかった場合は、**修復を行う周回の `run-dir` に上書き版を置く**。上流はそのまま保持する。
- 上書き版を置いた周回の `run-manifest.md` の冒頭に「上流 `run-dir` との関係」を 1 節として記録する。記録項目は、対象となる上流 `run-dir`、検出した欠陥の内容、上書き版で何をどう変えたか、上流を改変していない旨の 4 点。
- レポート作成者は、同じ処理について上流版と上書き版が併存する場合、上書き版を採用版として扱う。どちらが採用版かは上書き版の `run-manifest.md` の当該節が示す。
- 唯一の例外は、`outputs/` 等に認証情報などの秘密値が残っていたことが後から判明した場合の伏せ字化。この場合に限り当該 `run-dir` を直接修正し、`run-manifest.md` に伏せ字化した事実と日時を記録する。秘密値は残せば回収できないため、時点のずれより漏洩の回避を優先する。

## 認証情報の扱い

- 接続文字列・トークン・パスワード・API キーそのものを `scripts/` `run.sh` `environment.md` `outputs/` `run-manifest.md` のいずれにも書かない。
- 参照先の名前（環境変数名・シークレット名）のみを記録する。スクリプトは環境変数等から読み込む形で書く。
- 標準出力・標準エラーに秘密値が出る可能性がある場合は、保存前に伏せる。`outputs/` は成果物として残るため、一度書いたら回収できない。

## `run-manifest.md` — 読み手のための索引

読み手（レポート作成者・再現検証者）が `run-dir` 単体で内容を把握できるよう、以下を表形式で記録する。

| 記録項目 | 内容 |
|---|---|
| 実行順 | `<NN>` |
| スクリプト | `scripts/` 配下のファイル名 |
| 目的 | そのスクリプトが何をするか 1 行 |
| 入力 | 原データの識別子（台帳参照）または `derived/` のファイル名 |
| 生成物 | `derived/` `outputs/` `figures/` 配下の対応ファイル |
| 終了コード | 実測値 |
| 備考 | 失敗した場合の要約、採用／不採用、再実行で変わりうる箇所 |

先頭に、この `run-dir` が何の実行か（プロファイリング／分析第 `n` 周／再現追試第 `m` 周）と、`run.sh` の実行方法を 1 行ずつ書く。

## 本スキルが定めないもの

- 使用する言語・ライブラリ・分析手法の選択（要件シートと各周回のプランが決める）。
- データソースの台帳・ハッシュ検証・機密区分ごとの取り扱い（`analysis-data-handling` の責務）。
- レポート本文の構成・掲載方針（各サブエージェントの責務）。
